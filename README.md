## 1. 项目简介

TCM Medical RAG System 是一个面向中医临床场景的智能辅助诊断研究项目，结合医疗自然语言处理、检索增强技术与医学计算机视觉，实现从患者症状描述、历史病案检索到舌象特征识别的辅助诊断流程。

项目以中医临床病案及疾病编码映射知识库为基础，通过文本语义检索、相关性重排序和结构化信息匹配，辅助识别与患者症状相似的历史病例，并关联中医疾病、中医证型及西医疾病信息。

在文本诊断基础上，项目进一步引入舌象视觉分析模型，提取舌色、舌苔、裂纹及齿痕等特征，为后续文本与视觉信息融合提供依据。

**项目核心方向：**

- 医疗文本 RAG 检索与病案匹配
- 中医疾病、证型及西医疾病编码映射
- 舌象分割与多任务视觉分类
- FastAPI 推理服务与模块化系统集成
- 面向临床场景的多模态智能辅助诊断研究

> 本项目定位为医学人工智能研究与辅助诊断技术探索，系统输出用于辅助分析，不替代专业医生的诊断与临床决策。

## 3. 核心模块一：医疗文本 RAG

### 3.1 医疗知识库构建

针对中医临床病案中专业术语多、症状表达差异大、疾病表现存在重叠等问题，构建面向病案检索与疾病映射的医疗知识库。

知识库主要包含以下字段：

| 字段 | 说明 |
|---|---|
| 病史信息 | 患者症状及病史的自然语言描述 |
| 病史要点 | 提取或整理后的结构化临床表现 |
| 中医疾病_ICD | 中医疾病及其对应编码 |
| 中医证型_ICD | 中医证型及其对应编码 |
| 西医疾病 | 关联的西医疾病名称 |

**当前知识库规模：30,000+ 条医疗知识数据。**

主要处理流程：

1. 使用 Pandas、OpenPyXL 等工具读取和清洗医疗数据。
2. 对文本字段进行格式规范化、缺失值处理及数据质量检查。
3. 保留疾病名称、证型及编码之间的对应关系。
4. 对病史文本进行向量化，并建立可用于语义检索的索引。
5. 在检索阶段关联原始病案与疾病映射信息。

### 3.2 Embedding 向量检索

采用 `BAAI/bge-large-zh-v1.5` 作为中文文本向量编码模型。

核心流程：

```text
患者自然语言主诉
        |
        v
    BGE Encoder
        |
        v
   1024 维查询向量
        |
        v
    向量相似度检索
        |
        v
   Top-K 候选病案
```

主要作用：

- 识别语义相近但表达方式不同的症状。
- 匹配患者主诉与知识库中的历史病案。
- 为下游重排序与疾病映射提供候选结果。

例如，“胃部胀满不适”与“胃脘痞满”等表达可能具有较高的语义相关性，但具体匹配效果仍需通过验证集评估。

### 3.3 Reranker 重排序

采用 `BAAI/bge-reranker-large` 对初步召回的候选病案进行相关性评分。

```text
查询文本 + 候选病案
          |
          v
  BGE Reranker
          |
          v
    相关性评分
          |
          v
    候选结果排序
          |
          v
     Top-K 精选病案
```

与仅依赖向量相似度的排序方式相比，Cross-Encoder 类重排序模型能够联合分析查询文本与候选文本之间的相关性，为精细化病案匹配提供依据。

**当前版本说明：** 文本检索主链路以 BGE 向量召回和 Reranker 重排序为核心。BM25 关键词召回及混合分数融合可作为后续优化方向；只有在完成代码实现和效果验证后，才将其标记为已实现功能。

### 3.4 疾病与证型映射

基于候选病案关联的结构化字段，获取对应的中医疾病、中医证型及西医疾病信息。

针对中医辅助诊断的特点，可进一步结合不同临床信息进行匹配评分：

| 特征维度 | 参考权重 | 主要作用 |
|---|---:|---|
| 主症 | 35% | 识别主要症状与疾病方向 |
| 临床表现 | 45% | 提高细粒度病案匹配能力 |
| 舌象 | 10% | 提供辅助辨证信息 |
| 脉象 | 10% | 补充四诊信息 |

以上为参考评分方案，实际使用时应明确特征提取方式、分数归一化方法及权重应用位置，并通过独立验证集评估其有效性。

## 4. 核心模块二：舌象多任务视觉分析

为扩展文本诊断系统的输入维度，项目引入基于深度学习的舌象图像分析模块，提取与中医舌诊相关的视觉特征。

### 4.1 舌体分割

采用 YOLO-Seg 模型进行舌体实例分割，获得舌体区域及对应掩码，为后续分类提供感兴趣区域（ROI）。

处理流程：

```text
舌象原始图片
      |
      v
 YOLO-Seg 模型
      |
      v
 舌体区域分割
      |
      v
 ROI 裁剪与预处理
      |
      v
 EfficientNet 分类模型
```

分割模块的目标是减少背景、口腔周边区域等无关信息对舌象特征提取的干扰。

### 4.2 EfficientNet 多任务分类

采用 EfficientNet-B3 作为视觉特征提取与多任务分类的基础网络，对舌象的多个属性进行联合预测。

| 任务 | 识别内容 |
|---|---|
| 舌色分类 | 淡白、淡红、红绛等类别 |
| 苔色分类 | 白苔、黄苔等类别 |
| 苔厚分类 | 薄苔、厚苔等类别 |
| 裂纹识别 | 舌面裂纹相关特征 |
| 齿痕识别 | 舌体边缘齿痕相关特征 |

多任务学习能够在共享视觉特征的基础上，联合优化多个分类目标，减少独立训练多个模型带来的重复计算。

训练与评估过程中，应结合各任务的类别分布和样本规模，关注 Macro-F1、各类别召回率以及混淆矩阵，尤其需要评估少样本类别的泛化能力。

### 4.3 舌象结构化输出

视觉模型的预测结果可以转换为结构化特征，供后续诊断信息整合模块使用。

示例：

```json
{
  "tongue_color": "红绛",
  "coating_color": "白",
  "coating_thickness": "薄",
  "crack": true,
  "teeth_mark": false
}
```

以上仅为输出格式示例，不代表实际模型已达到对应的诊断准确率。

## 6. 技术难点与解决思路

### 难点一：医疗症状存在多样化表达

**问题：** 患者自然语言描述与标准医学术语之间存在差异，单纯依靠字符串匹配容易遗漏语义相关的病案。

**解决思路：** 使用中文医学场景适用的 BGE 向量模型建立语义表示，并通过候选病案重排序提升检索相关性。

### 难点二：相似症状可能对应不同疾病

**问题：** 多种疾病可能具有相似的临床表现，仅依靠单个症状难以进行可靠区分。

**解决思路：** 将主诉、临床表现、舌象及脉象等信息作为不同证据维度，并结合知识库中的疾病与证型映射，为医生提供可追溯的候选结果。

### 难点三：视觉模型存在类别不均衡问题

**问题：** 舌象数据中部分特征类别的样本较少，可能导致模型对少数类别的识别能力不足。

**解决思路：** 通过数据增强、合理的任务损失权重及分类别指标分析，评估模型的泛化能力，并持续补充具有代表性的标注数据。

### 难点四：文本与图像结果的可靠整合

**问题：** 文本检索结果与视觉分类结果具有不同的置信度和误差来源，直接拼接可能引入错误信息。

**解决思路：** 对不同模态的输出进行结构化管理，保留来源与评分信息，并在验证集上评估融合策略；对低置信度或相互冲突的结果保留不确定性提示。

## 8. 后续优化方向

### 检索能力优化

- 引入 BM25 稀疏检索，与 BGE Dense Retrieval 进行混合召回。
- 通过验证集比较不同召回策略和 Top-K 参数。
- 评估 Reranker 对 Recall@K、MRR、NDCG 等检索指标的影响。
- 优化知识库去重、字段规范化及编码一致性检查。

### 医疗知识增强

- 扩充经过授权与质量审核的中医临床病案。
- 引入规范化医学知识及疾病、证型之间的关联信息。
- 建立可追溯的检索结果与疾病映射记录。

### 多模态诊断优化

- 完善舌象视觉模型的分类别评估与少样本学习。
- 研究文本症状、舌象和脉象的特征级或决策级融合。
- 评估不同模态缺失、预测冲突及低置信度场景下的系统表现。

### 工程化部署

- 优化模型加载、推理延迟与显存占用。
- 增加日志记录、异常处理及接口测试。
- 完善模型版本管理、数据质量监控与诊断结果追踪。
